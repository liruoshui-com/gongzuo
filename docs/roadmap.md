# 路线图

衡量进展的中心是：普通用户能否以更少的总 token、更少返工、更短时间，做出合格且保留个人特点的成果。

## 当前：0.3 公开预览

- 自由目标、个人要求、材料、执行和成果版本。
- 多家 API 预设，按需读取材料，本地 CSV 工具。
- 调用上限、真实返回用量、人工验收。
- 上下文预检、逐请求元数据、早期补充遗漏与重叠读取提示。
- 用户可固定重要要求，并人工标记已带入但未落实的要求；体检额外模型调用为 0。
- 模拟协议和浏览器验证已完成；真实效果尚未测量。

## 接下来：先拿到真实证据

1. 使用真实可用账号跑通三个任务方向，记录失败，而非仅记录成功演示。
2. 完善完整任务的 token、耗时、修改次数及验收记录。
3. 对比普通聊天、固定专业提示词与共作；公布质量、个人要求得分和每个合格成果的总消耗。

## 根据测量结果优化

- 若上下文输入占主要消耗：减少重复读取，设计保留依据的工作记忆和必要的压缩。
- 若重写整份文件占主要消耗：增加可以检查的局部修改和版本差异。
- 若选错模型造成返工：评估按任务步骤选择模型，并记录选择代价；不默认堆叠多代理。
- 若用户反复交代个人要求：让可编辑、可撤销的偏好卡参与每次成果检查。
- 若文件兼容是主要障碍：优先补充有实际需求的原生办公格式与工具。

以上属于待验证设计，不是已具备能力。不能以更低质量换取看起来更低的 token 数。
