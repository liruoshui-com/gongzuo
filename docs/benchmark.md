# 共作：竞品证据与首轮真实测试

测试日期：2026-09-13。当前结论：**按需读取在不同任务上的效果不同，尚不能声称共作普遍更省 token、更快或让新手成果达标。** 本轮同时保留正面、负面结果和未完成运行。

共进行了 **56 次真实请求（包含 1 次连接检查）**，累计 **237,858 token**：输入 202,758、输出 35,100；缓存输入 160,640 已包含在输入中。按返回用量及当日价格估算 **0.1857308 元，约 0.19 元**，低于用户授权的 5 元；按峰价且不计缓存优惠的保守累计值为 0.686316 元。没有继续消耗剩余额度。

## 竞品究竟省了多少

下表是开发者论文或官方文章的结果，未在本轮独立复现。数据集、模型、成本范围不同，不能当成同一场排行榜。

| 产品 / 资料 | token 或上下文变化 | 时间变化 | 质量及计量边界 |
|---|---|---|---|
| Mem0，2025 年论文 v1 | 检索上下文 26,031 → 1,764，减少 93.2% | 回答 p95 17.117 → 1.440 秒，减少 91.6% | 同一全文基线的评分 72.90 → 66.88，下降 6.02 个百分点。宣传的质量提高 26% 使用了另一条 OpenAI Memory 基线。未把记忆构建和所有生成成本一起计入上下文 token。 |
| Zep，2025 年论文 v1 | LongMemEval_s 上 115K → 1.6K，减少约 98.6% | 回答 28.9 → 2.58 秒，减少约 91.1% | GPT-4o 准确率 60.2% → 71.2%。表中时间不是 p95；上下文量不等于图谱构建、检索、生成的完整成本。 |

来源：[Mem0 论文](https://arxiv.org/html/2504.19413v1)、[Zep 论文](https://arxiv.org/html/2501.13956v1)、[Claude 上下文管理](https://claude.com/blog/context-management)、[Letta 基准](https://www.letta.com/blog/benchmarking-ai-agent-memory/)。

这些收益主要来自长对话和记忆检索。我们的三份材料只有 569、339、357 个 JavaScript 字符，不应期待它们复现长上下文实验的九成降幅。缓存降价也不等于 token 减少；例如 [OpenAI 的缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)描述的是缓存输入的折扣。输出生成、调用轮次和网络等待都会影响速度，见[延迟说明](https://developers.openai.com/api/docs/guides/latency-optimization)。

## 我们实际测了什么

使用用户授权的 **DeepSeek 官方 `deepseek-flash`**，非思考模式、temperature 0。同一真实执行器、工具、目标、固定要求、验收条件及修改反馈；只改变材料与已有成果是全文带入还是先给目录、按需读取。预设合成真值供评分使用，没有进入模型任务。

- 研究：从三份材料比较采购方案，输出建议与 JSON；随后将预算从 300 元降到 220 元。
- CSV：保留前导零、重复记录和未知工时，先按部门、再按标签汇总；总工时真值为 17。
- 产品：生成可离线保存的学习记录页，再增加标签筛选；实际用 Edge 操作新增、补记历史日期、刷新、删除与筛选。

每阶段最多 4 次请求、4,096 输出 token、24,000 总 token 软限。首轮全局 40 次请求上限触发，保留了产品按需组初版，未进入修改阶段；随后另建实验目录补做产品的完整配对。没有替换或删除首轮失败，补跑消耗也计入账目。

这测量的是**起始上下文策略**，并非普通聊天、专业提示词、共作三种完整产品的比较。两组都已有结构化任务说明和固定要求；没有招募新手，也没有测用户操作、思考和人工验收时间。

## 实际资源使用

各行包括初版及一次固定修改的所有请求。正负方向直接写明，避免把“增加”包装成节省。

| 任务 | 全文组总 token | 按需组总 token | 按需组变化 | 全文组执行秒数 | 按需组执行秒数 | 时间变化 |
|---|---:|---:|---|---:|---:|---|
| 研究，首轮 | 24,528 | 25,248 | 增加 2.94% | 17.486 | 17.070 | 减少 2.38% |
| CSV，首轮 | 25,408 | 21,173 | 减少 16.67% | 11.091 | 10.379 | 减少 6.42% |
| 产品，补跑 | 43,204 | 41,920 | 减少 2.97% | 27.295 | 33.836 | 增加 23.96% |

**上表是给定轮次预算内的资源差异，不是到人工合格为止的节省率。** 研究按需组的修改阶段、CSV 两组的两个阶段，都达到 4 次调用上限；产品补跑全文组修改阶段达到 24,000 token 软限。虽然这些阶段交付的文件通过自动检查，完整运行仍标为 blocked。初版产品未配齐的首轮不计算配对降幅。每题只有一次完整配对，缓存及执行顺序可能影响结果，几百毫秒差异不能证明稳定提速。

首轮研究费用估算：全文 0.01929532 元、按需 0.01721384 元；CSV：全文 0.00973336 元、按需 0.00981300 元；补跑产品：全文 0.03825028 元、按需 0.03746444 元。**CSV 按需组 token 较少，但本次金额略高；产品 token 少了，等待反而更久**，说明不能忽略缓存命中、输出构成和调用轮次。

执行计时包含网络、工具和落盘，自动验收耗时另列，不包含人的工作时间。输入与输出相加得到总 token，缓存输入与推理输出不重复相加；未知用量不补零。费用按[DeepSeek 当日官方价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)及周日谷时计价估算：每百万未缓存输入 1 元、缓存输入 0.02 元、输出 4 元。预算保护使用更保守的峰时价格，不等于账单核销。

## 成果是否真的更好

固定自动检查与补充人工审查分别保留。补充审查由代理查看已知组别的成果完成，**不是独立人类盲评**，没有事后修改评分规则。

- **研究：**两组初版与修改版的核心决策、月费、年化值和不采购结论正确，自动检查通过。但都把“供应商声明支持 CSV 导出”扩大表述成“声明导出完整性”；修改版还把用户新给的 220 元预算归引到仍写 300 元的 S3。尚不能算来源语义完全通过。
- **CSV：**数据和汇总均符合独立真值，特殊字符、前导零、重复记录、空工时均保留。但检查说明把编号计算为合计、最小值和最大值，没有业务意义，容易误导；这说明确定性工具也需要任务语义约束。
- **首轮产品：**全文组两个版本因日期与标签的可访问名称包含额外提示，未满足预先约定的精确命名；按需初版通过原检查。补充浏览器操作确认三份页面的核心新增、补记、保存和删除均可用，全文修改版的中文标签筛选也可用。额外健壮性检查发现全文版在存储异常后误报保存成功，以及 `constructor` 标签未进入筛选选项。不能把精确命名失败直接解释为整个产品不可用，也不能仅因正常路径可用而忽略异常处理。

产品补跑的两个策略、两个阶段共四份页面均通过预设的真实浏览器功能检查，但全文组修改运行因软限停止。补充只读检查显示，补跑两份修改版有保存失败提前返回逻辑；按需版仍漏掉 `constructor` 标签筛选选项，全文版对 `__proto__` 标签可能生成重复选项。它们是新增的边界观察，不改变原中文标签评分，也不能证明哪种策略整体更好。

补跑与原首轮同时保留。本轮未计算“全部 token ÷ 人工合格任务数”，因为尚未形成事先约定的人工合格判定。

## 上下文体检与标注数据

17 个显式标注的合成结构场景，各用 3 种接口协议执行，共 **51/51 通过**。对七类结构标签的微平均：TP 30、FP 0、FN 0、TN 327，精确率和召回率均为 100%。协议变体彼此相关，不能当成 51 个独立真实任务；标签在检查前写入，但不是独立人类标注研究。

体检会检查固定要求是否进入请求、较早反馈何时被裁剪、读取版本与范围、重复读取，以及旧记录缺失等。上述准确率只对这批结构案例有效，**不是识别 AI 遗忘、理解错误或需求落实的准确率**。实际任务里“已带入”的要求，仍可能在成果中表述不准。

本轮 **55 次任务请求**都保存了上下文元数据（连接检查不属于任务）。245 次目标、个人要求、验收条件和固定要求的检查全部显示已带入，其中固定要求检查 80 次；出现 4 次请求显著增长提示。这里的 245 是请求与要求的组合次数，不是 245 条独立用户需求，也不能证明全部落实。

本地体检及这 51 个检查 **新增模型请求 0 次**。固定要求本身会增加模型输入：本轮研究 / CSV / 产品分别有 1 / 1 / 2 条，共 30 / 31 / 66 个正文字符；相比同请求的空固定要求列表，序列化请求增加 78 / 79 / 148 个字符（UTF-16 口径，含结构与转义）。**这不是 token 数**，没有单独做有无固定要求的 token 消融测试；其消耗已包含在真实请求总量中。

## 下一步由数据决定

优先验证短材料直接带入、长材料按需读取的选择规则，减少为目录、计划和重复交付增加的往返。随后检查 CSV 已完成后能否更及时结束，改善生成产品的保存异常与真实任务验收，再加入长文、多轮反馈和新手使用测试。上下文体检应先帮助定位遗漏与额外调用，不能用结构覆盖率代替成果质量。

原定的 9 任务 × 3 方法 × 2 次（54 次）新手/专业提示/共作实验仍属后续计划，本轮没有完成该设计。后续应预先登记质量规则、匹配工具与模型、记录全部失败和修订，并在质量与个人要求未下降时报告合格任务的总消耗。
